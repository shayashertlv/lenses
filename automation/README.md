# Glasses reconstruction automation

## Routes

This folder holds five routes. Which one is current is the owner's decision; the paragraphs after this list describe
`segmented_ar_v1` as its own documents last recorded it.

- `segmented_ar_v1` (`reconstruction/`): [the job contract](plan/SEGMENTED_AR_JOB.md). Tripo generation and
  segmentation, optical candidates and actual AR rendering; the 2026-09-24 route decision kept this route.
- BSA, Best-Source Assembly (`bsa/`): [bsa/DESIGN.md](bsa/DESIGN.md). Each part comes from the source that measures it
  best, parts are assembled by construction and every output is scored against the photos (M0 + M1, no paid calls).
- Modeler, the legacy per-turn loop (`python -m modeler.job`): [modeler/README.md](modeler/README.md). An AI author
  writes Blender construction programs; the host builds, observes and exports them through the BSA contract.
- Modeler, the agentic route (`python -m modeler.agentic`): [modeler/agentic/README.md](modeler/agentic/README.md).
  The same author as one durable, budgeted, recoverable conversation per product.
- Live Blender agent (`python -m blender_agent`): [blender_agent/README.md](blender_agent/README.md).
  Experimental autonomous Astra session using the standard Agents SDK and community Blender MCP, with a persistent
  editable scene, native full-geometry export and actual AR feedback. The [local studio](blender_agent/STUDIO.md)
  adds image intake, optional Gemini web research for sourced specifications, budgeted runs and shared 3D/AR material controls;
  launch it with `agentic-studio.cmd`. This opt-in route leaves the live Railway application unchanged.

Current route: [`segmented_ar_v1`](plan/SEGMENTED_AR_JOB.md), with an opt-in [canonical Astra editing stage](plan/SEGMENTED_ASTRA.md). The stage edits retained source parts and optical descriptors, recompiles through the strict optical contract, and observes the result in actual AR before promoting a checkpoint. See the Astra runbook for current validation status; implementation and runtime checks do not establish photographic accuracy. The [earlier readiness audit](plan/ASTRA_READINESS_2026_09_23.md) is historical. The separate Blender editor remains incompatible with these optical assets.

Target: existing product photos and optional dimensions to an accurate-looking 3D glasses model for AR try-on, without per-product modeling work.

The **`segmented_ar_v1` job now runs the successful Tripo route end to end**: retained generation and segmentation, bounded face correspondence, multi-view automatic lens identity, guarded normal repair, image-grounded optical candidates, actual AR rendering and reversible delivery. See [the command and function contract](plan/SEGMENTED_AR_JOB.md) and [five-product results, comparisons and remaining limits](plan/SEGMENTED_AR_RESULTS_2026_09_23.md). Clear lenses, ordinary tint, brown gradient and colored mirrors are exercised. These are reviewable candidates: frame detail, ambiguous lens-edge identity and exact mirror appearance remain quality limits.

The [six-generation API comparison](plan/API_COMPARISON_RESULTS_2026_09_23.md) now tests Rodin Gen-2.5, Tripo H3.1/v3.5 textures and TRELLIS.2 against original cached Meshy outputs on Oakley and rimless Miu. Tripo is the strongest new candidate in the inspected images, but still produces fused, opaque, high-polygon assets. Lens face identification, optical assignment and mobile simplification remain necessary; no provider output was accepted as a finished AR asset.

The preceding [parts experiments](plan/PARTS_EXPERIMENT_RESULTS_2026_09_23.md) test automatic segmentation, native parts generation, render-image SAM3 masks and guided segmentation on Oakley and rimless Miu (ten paid inference calls). Segmentation of the retained textured model is the best tested route: both products have editable transparent-lens candidates that pass actual AR loading after measured simplification and compaction. Native Oakley generation introduces lens notches; guided Miu omits a thin optical strip from the main lens parts. A controlled reflection test also shows that the Oakley white rectangle is live optical response, not leftover opaque lens geometry. The job described above builds on that experiment. The earlier [parts strategy review](plan/PARTS_STRATEGY_RETHINK_2026_09_23.md) is retained as the pre-experiment rationale.

The five-workstream implementation now connects automatic camera/temple articulation, fused-face and bounded missing-surface repair, conservative frame relighting, grounded front/rear optical hypotheses, and measured AR delivery. See [implementation and measured limits](plan/BUILD_1_TO_5_RESULTS.md) and the [function-level build contract](plan/BUILD_1_TO_5.md). This produces tested candidates and explicit failure/review reports; it does not yet certify product accuracy automatically.

The complete job can [reserve existing photos for final evaluation](plan/EVALUATION_PHOTOS.md), prevent provider/semantic input leaks, bind evaluation to one final candidate, and recompute source-bound front/temple support. Frame corrections now require independent image membership; complete-area coverage uses surface samples rather than atlas texel density.

The latest repair pass adds omitted optical-fragment proposals, bounded smooth lens-normal alternatives, grounded image color evidence, shared paired-lens materials, rear-view transmission candidates, and bounded mask search to `semantic_ar_v1`. It also fixes provider continuation and shared submission allowances. See [current pipeline status and remaining work](plan/PIPELINE_STATUS_2026_09_23.md); the pipeline still does not establish finished product accuracy automatically.

The opt-in `semantic_ar_v1` appearance path now interprets photographs with an explicitly configured vision client, measures conditional tint anchors, adds bounded reflection lighting to the joint fit, exports competing materials, renders them through the actual AR engine and compares them twice with candidate order reversed. User-supplied lens facts remain authoritative; inferred hypotheses remain fallible. See [implementation, evidence and remaining gaps](plan/IMPLEMENTATION_2026_09_23.md). A cached job can run this path with `python -m reconstruction.semantic_appearance_stage --job <job> --output <new-output> --semantic-report <saved-report> --api-key-env GEMINI_API_KEY --cache <new-cache> --maximum-api-calls 2`. Omitting a semantic report also requires one interpretation call, so use a three-call budget. New jobs select `--appearance-mode semantic_ar_v1 --semantic-api-key-env GEMINI_API_KEY --semantic-cache <cache>` alongside physical group inference and joint fitting. The default photo-only selection is unchanged.

Automatic source-face/hinge binding, per-photo articulation and shared-shape fitting are connected through the projection and ray consumers. Grounded rear color now participates in joint front/rear fitting under separate reflection hypotheses. Independently observed rear-object templates can support contrast transmission constraints; unavailable or ambiguously registered templates remain unmeasured.

The current deliverables include a resumable job flow for photo intake, initialization, geometry refinement, region observations and optional optical candidate preparation/fitting, plus verified Blender/GLB/browser lens-response paths and a bounded optical profile in the actual AR renderer. This is not a finished reconstruction pipeline. See [the job contract and commands](plan/JOBS.md), [the initial plan](plan/README.md), [the architecture review](plan/ARCHITECTURE.md), [geometry refinement](plan/GEOMETRY_REFINEMENT.md), [product-photo optical candidates](plan/PHOTO_LENS_PIPELINE.md), [lens conformance](plan/LENS_CONFORMANCE.md), [AR integration](plan/LENS_RUNTIME.md), and [current evidence](plan/PROGRESS.md).

The [photo-observation contract](plan/SEMANTIC_OBSERVATIONS.md) documents the offline region engine, fixed prompt policy and conditional color measurements now connected to jobs. The [optical candidate stage](plan/PHOTO_LENS_PIPELINE.md) explores tint, gradient and angular mirror explanations using actual exported UV/normals. Lens/frame identity and optical material identification remain unverified; returned masks or fitted materials do not establish acceptance.

The [image-only semantic experiment](plan/PHOTO_SEMANTIC_INFERENCE.md) adds a frozen 24-photo baseline and semantic-to-SAM proposal runner. It exposes frame contamination, reflected-product duplicates and confident unrelated-object predictions. These QA tools preserve alternatives and do not assign production materials. The same review corrects the earlier Miu diagnosis using actual source components and defines the face-partition/group evidence needed next.

The [source-component and face-partition stages](plan/FACE_PARTITIONS.md) now preserve complete triangle lineage while splitting a source primitive into explicit pieces. A verified adapter binds piece-group hypotheses to the existing optical preparer using fresh output indices. Connectivity is inventory, and supplied partitions are hypotheses; automatic semantic assignment and observation translation remain unfinished.

The [component/aperture evidence stage](plan/COMPONENT_APERTURE_EVIDENCE.md) now relates independent photo proposals to every source component, including hidden and subpixel pieces. A fixed five-design, ten-view run retains 667 components and 128 aperture alternatives, with directional coverage and depth relationships. The [shared support optimizer](plan/SUPPORT_UNION_INFERENCE.md) then infers component unions across views; all twenty fixed coarse branches completed. Physical group membership remains separate: overlapping shells can be omitted from an optimal support set, while rear geometry can improve a misleading aperture fit. These hypotheses do not assign lens materials.

The latest front-envelope conversion failed the fixed corpus: no complete model prepared. That path is frozen. A [source-preserving optical-group alternative](plan/OPTICAL_GROUPS.md) retains closed and multipart geometry under an explicit experimental profile. A separate frozen-fit diagnostic audits validation coverage and residuals without changing fitted parameters or selecting new masks.

The [physical-group stage](plan/PHYSICAL_GROUPS.md) now turns that evidence into competing partitions over every source component: a fixed depth-tolerance ladder merges coincident surfaces, attaches coincident fragments without letting them bridge groups, keeps separated layers and partial overlaps apart, and evaluates optical/non-optical role evidence per aperture branch without feeding it back into membership. A per-pixel ray-composition map then states what each photographed pixel would contain under a hypothesis (lens over background, lens over rear geometry, frame in front, stacked lenses, no geometry). The fixed five-design run produces the expected lens groups on all five, exposes the front/back-sheet ambiguity on RayBan and the strut over-merge on Oakley as separate hypotheses, and passes the consensus optical candidates through the unchanged partition and preparation bridge. These are hypotheses with visible failures, not verified lens identities. A bounded appearance pilot on the bridged Miu candidate (`qa.physical_group_pilot`) ran the unchanged region stage and grouped joint fit end to end: the ray-composition ledger and the observer's coverage agree within 0.004, photo errors fall to 3–5 codes from the 6–19 of the earlier VB experiment, but no candidate passes the photo policy, one lens has no validation support under the fixed spatial split, and the five families remain indistinguishable on a clear lens over a white backdrop.

The alternative has a strict GLB exporter/reader, a photo adapter and an [explicit grouped job mode](plan/GROUP_JOB_ADOPTION.md). Closed and multipart groups feed the existing joint fitter and load through the [local AR group path](plan/EFFECTIVE_GROUP_RUNTIME.md). Jobs can prepare automatic source-part hypotheses or source-bound declarations; both remain unverified. The default front-sheet mode is unchanged. Representation and recovery support do not establish semantic identity or material accuracy.

## Run the current segmented job

Use `python -m reconstruction.job --request request.json --output data/jobs/example` with `"pipeline": "segmented_ar_v1"` in the request. The [segmented job contract](plan/SEGMENTED_AR_JOB.md) supplies the complete provider, semantic-client and recovery options. `python -m reconstruction.segmented_job --help` lists that route's current CLI options.

Run the optional Astra stage against a completed segmented job, keeping its output separate:

```powershell
python -m reconstruction.segmented_astra_job --base-job data/jobs/example --output data/astra/example-scripted --astra-script plans.json --astra-max-turns 2
```

This scripted mode makes no paid inference call. Live mode requires `--authorize-paid-astra`, an explicit credential source, and a shared `--astra-budget` ledger with `--astra-maximum-calls` between 1 and 10. To include it after the base job, use `reconstruction.segmented_job --with-astra` with those same options. See [the Astra runbook](plan/SEGMENTED_ASTRA.md) for complete commands, typed tools, coordinate conventions and recovery rules. The base asset stays preserved; `report.json` identifies the separately compiled current candidate. Neither a model's `finish` nor successful AR loading marks it production-ready.

## Legacy reconstruction jobs

```powershell
python -m reconstruction.job --request C:/path/request.json --output data/jobs/example
```

With `--optical-grouping physical_group_inference --aperture-weights data/models/glasses-detector-v1` (plus lens candidates, joint fitting and a region engine) the job infers the physical lens groups from the photos and geometry, fits the appearance families on the bridged candidate, selects the least complex family within tolerance of the best error (the photo policy never narrows that pool: on a white backdrop a clear lens and a mirror of a white environment give the same pixels), and writes `candidate-appearance.glb` beside `candidate.glb`; the selection rule and every alternative are recorded, `photo_policy_pass` describes the shipped preview and `policy_verdict` says whether an equally supported alternative is within policy, and nothing is marked accepted. The fit keeps rear-content samples (lens rays that meet a temple, pad or frame behind the lens) out of the residual and the photo policy by default (`rear_content: excluded`), because one unknown rear colour cannot explain structured rear content; the ledger counts them. A `surface_transfer` stage moves the retained textured generation's UVs, material and textures onto the split parts by closest surface point, one texture-atlas island per face (vertex colours dropped, seam vertices duplicated), so the frame carries the provider's photographic bake in AR. A declared `lens_facts.mirror_coating` (product data, like the dimensions) keeps only the mirror families or only the tints in the fit, because a photograph cannot tell a mirror coating from a bright reflected studio. A stated `frame_width` scales the initial model to metres across its X extent in a `scale` stage (the provider bytes stay untouched) and is also offered as the AR load width (`ar_load_parameters`); the AR runtime fits the wearer from the model's own metres, so a raw provider generation cannot be placed without it.

The photos-only front end is exercised: `"initializer": {"kind": "meshy", "split": {}, "provider_views": [...]}` runs the provider generation and then a second paid task that splits it into named parts, retains the textured generation as `generated.glb` and hands the split parts to the same chain (`--meshy-max-new-tasks 2`; see [the job contract](plan/JOBS.md)). `qa.refit_job` refits a completed job's joint stage under a changed fit policy without rerunning the earlier stages, and `qa.replay_group_stage` replays a job's physical-group stage under the current code and reports any change of consensus membership or selection. Roles pool the inside share over views with a per-view floor and measure cover against the aperture blobs a group lands in; a group that is optical under some aperture branches gets a `branch_optimistic` entry ranked by composition beside the consensus entry; the rank judges contamination in the most-visible view first; a (group, photograph) whose projection lies mostly outside its aperture is excluded from the fit as badly registered; and exactly coincident faces shared by two split parts (a wall behind a lens, the cut between two halves) are interior contacts, kept out of the projection and of every optical group and omitted from the runtime candidate. All of this was forced by the first raw provider model, and the five archived designs replay unchanged under it.

The request accepts two or more distinct photos, optional/repeated angle labels, optional dimensions, and an optional existing GLB initializer. [The request format](plan/JOBS.md) explains the fields, explicit provider credentials/submission allowance, and `--lens-candidates` option. Repeat the command to verify and reuse completed stages or resume interrupted work. A job can produce a candidate, but current semantic/optical/independent quality coverage remains unmeasured. Without a supplied model or an explicitly configured provider backend, a photo-only job prepares initialization and reports that it is awaiting a backend; it does not claim a completed model.

## Reproduce the saved-run audit

From this directory, using Python 3.10 or later:

```powershell
python audit_saved_runs.py --jobs-dir ../ar_v4/modeling_auto/data/jobs --output plan/baseline-inventory.json
python -B -m pytest tests -q -p no:cacheprovider
```

The audit reads direct saved job records and verifies normalized reference-image hashes. It does not import either modeling application, alter a job, load credentials or call a provider. It reports workflow state, duplicate input sets and seam-measurement coverage. These are evidence inventory checks, not reconstruction-quality scores.

The generated inventory stays local and is ignored by Git. Existing modeling applications and the live AR app are not modified by this audit.

## Experimental reconstruction tools

For a fresh segmented environment, run `python -m pip install -r requirements-segmented.txt` from `automation/` with Python 3.12. This includes the original numerical requirements and the additional provider, reduction and offline aperture packages. The historical Blender editor has a separate Python environment at `ar/modeling/.venv`; installing one does not configure the other. The AR Node dependencies, Playwright Chromium and pinned offline lens weights are covered in [the active job setup](plan/SEGMENTED_AR_JOB.md#runtime-and-asset-boundaries) and [the Astra runbook](plan/SEGMENTED_ASTRA.md). These prerequisites are already present on the current host; no installation is needed there.

- `reconstruction.segmented_job` / `segmented_providers`: the current Tripo-to-AR route, immutable stage recovery, explicitly configured provider/semantic clients and optional canonical editing. See [the current job contract](plan/SEGMENTED_AR_JOB.md).
- `reconstruction.segmented_astra_job` / `segmented_astra_session` / `segmented_astra_tools`: opt-in typed edit decisions, verified authoring checkpoints, strict compilation, restoration and separate current/base candidate reporting. See [the Astra runbook](plan/SEGMENTED_ASTRA.md).
- `reconstruction.segmented_astra_geometry` / `segmented_astra_observe`: bounded source-part geometry/material edits with preservation proofs, actual-AR comparisons and source-bound part labels; neither local guards nor visual inspection confer product acceptance.
- `reconstruction.segmented_astra_transport`: explicitly authorized Responses requests, one shared ceiling of at most ten reservations, immutable paid-attempt receipts and verified local replay; no hidden retry or model fallback.
- `reconstruction.observations`: conservative studio-background contrast evidence, with explicit missing semantic/optical coverage.
- `reconstruction.region_engine` / `region_proposals` / `photo_appearance`: explicitly configured offline SAM2 alternatives, candidate-bound region priors, prompt ambiguity, interior signal statistics and height/incidence hypotheses. Use the job's `--region-weights` option with an existing local checkpoint; nothing is downloaded.
- `reconstruction.input_bundle` / `initializer` / `job`: immutable original/normalized photos, preserved optional dimensions, exact model imports, explicitly injected resumable provider operations and stage/artifact recovery. No default credential discovery or network execution.
- `reconstruction.meshy_transport`: bounded opt-in HTTPS transport with one reserved submission per instance, explicit credential source/estimated-cost allowance and recovery by saved task ID; the split endpoint is a second instance. Software tests use mocked HTTP; provider generation quality remains unmeasured.
- `reconstruction.metrics`: component mask and contour measurements, coverage and directional errors. Missing reference evidence is unmeasured; missing candidate geometry is measured failure.
- `reconstruction.mesh` / `camera`: static GLB loading, triangle-union rendering and bounded photographic camera fitting.
- `reconstruction.evidence`: immutable image-bound component evidence, including unknown/occluded/absent states and normal-only image edges.
- `reconstruction.edge_correspondence` / `raster`: candidate-guided edge hypotheses and perspective-correct visible surface sampling.
- `reconstruction.deformation`: one shared 3D cage, camera/scale gauge, normal-only constraints, data-only observability diagnostics and nonregression checks.
- `reconstruction.deform_glb` / `refine_photos`: preserve asset materials/UVs while proposing bounded geometry changes, checking exported triangles, and rerendering the actual output.
- `reconstruction.lens_appearance`: versioned linear-light reference equations separating spatial absorption, angular reflection and energy accounting.
- `reconstruction.blender_lens_material`: experimental Blender shader compiler for that effective single-surface response.
- `reconstruction.lens_asset`: controlled GLB fixtures carrying the complete canonical material, semantic identity and local coordinates. Generic glTF fallback is explicitly approximate.
- `reconstruction.lens_fit`: robust inverse fitting of calibrated optical samples, with explicit parameter-identification, ambiguity and model-mismatch evidence. This is a development instrument, not an extractor for ordinary product photos. See [the inference experiment](plan/LENS_INFERENCE.md).
- `reconstruction.optical_surface` / `prepare_optics` / `optical_asset`: measured front-envelope preparation and reversible export with exact geometry/material bindings, preserving unrelated source content.
- `reconstruction.photo_lens_observations` / `photo_lens_fit` / `photo_lens_stage`: actual prepared-coordinate photo samples, bounded material/lighting alternatives, coverage and diagnostic GLB previews. No material is automatically accepted. See [the product-photo contract](plan/PHOTO_LENS_PIPELINE.md).
- `reconstruction.joint_photo_lens_fit` / `joint_photo_lens_stage`: shared lighting/exposure per photograph with independent group materials, complete bounded mask branches, factorized roughness and resumable optimizer starts. See [the fixed comparison protocol](plan/JOINT_PHOTO_EVALUATION.md).
- `reconstruction.photo_lens_derivatives`: verified analytic derivatives of the existing objective, available as an explicit joint-stage option. The faster mode does not establish convergence or material identification.
- `reconstruction.optical_identity`: candidate-conditioned cross-view associations through visible source triangles, preserving split/merge ambiguity and missing visibility. Region ordinals and source labels never become verified identities.
- `reconstruction.mesh_components` / `partition_glb` / `partition_stage`: exact component inventories and source-preserving face partitions, with an independent byte/lineage verifier. `partition_optical_groups` resolves explicit piece hypotheses to fresh optical declaration bindings. See [the partition contract](plan/FACE_PARTITIONS.md).
- `reconstruction.aperture_evidence` / `component_projection`: verified image-only aperture alternatives, complete per-component projection and overlap/depth evidence. Crop exteriors remain unknown; all-opaque visibility is only a diagnostic. See [the evidence contract and fixed corpus](plan/COMPONENT_APERTURE_EVIDENCE.md).
- `reconstruction.support_union`: bounded inference of a shared component subset maximizing worst-view aperture IoU, with recomputed union metrics, conditional solver bounds and explicit membership ambiguity. It selects support hypotheses, not physical groups or materials. See [the fixed policy and results](plan/SUPPORT_UNION_INFERENCE.md).
- `reconstruction.physical_groups`: competing physical-group partitions over complete source components from projected co-occupancy and depth agreement at an explicit tolerance ladder, per-branch role evidence, and partition/piece-group declarations for the existing exporters. No material, name or role enters membership. See [the policy and fixed run](plan/PHYSICAL_GROUPS.md).
- `reconstruction.ray_composition`: per-pixel photographed-ray classes under one group hypothesis (lens over background, lens over opaque or unresolved rear geometry, frame in front, stacked optical, no geometry, ties), with per-aperture accounting for the appearance fit.
- `reconstruction.photo_apertures`: the pinned Glasses Detector v1 lens head as an explicit offline engine (full-image and contrast-crop unions with known domains); it reproduces the frozen baseline masks bit for bit and is the job's photos-only aperture source.
- `reconstruction.component_scene`, `physical_group_stage`, `appearance_selection`: the job stage that inventories components, projects them under the refinement cameras, infers group hypotheses, composes rays, ranks hypotheses by composition, bridges every distinct consensus declaration with a verified camera transfer, and the explicit least-complex-family-within-tolerance selection over fitted previews. Selected with `--optical-grouping physical_group_inference --aperture-weights <folder>`; see [the job contract](plan/JOBS.md).
- `reconstruction.candidate_cameras`: verified transfer of fitted cameras from an original candidate to its face partition (receipt verification plus world-triangle multiset identity), so the unchanged region and observation stages accept a partitioned candidate. The grouped observer now records region priors that touch undeclared lens-material pieces as unbound instead of failing.
- `reconstruction.composition_diagnostic`: pinned overlays and measurements of front/rear geometry and unexplained photographic structure before material fitting. This does not infer arm articulation or distinguish reflection from frame structure.
- `reconstruction.optical_groups` / `optical_group_raster`: experimental source-preserving group coordinates and nearest-event geometry. Explicit group identity remains unverified.
- `reconstruction.prepare_optical_groups` / `group_photo_lens_inputs`: source-preserving preparation, complete membership/declaration binding and the grouped joint-fit adapter. The job exposes this explicitly through `--optical-profile effective_optical_group_v1_experiment --optical-grouping source_part_hypotheses --lens-candidates --lens-fit-mode joint`.
- `reconstruction.optical_group_asset` / `optical_group_observations`: source-bound experimental GLB export, captured-byte reload and photo samples from actual exported attributes. Closed/multipart groups retain their source triangles; float32 conversion and coincident patches are checked.
- `reconstruction.optical_group_validation` / `optical_group_runtime`: bounded exact checks of coincident patches, nonzero interpolated normals and a common group-height mapping in float32 rounding enclosures. These do not certify semantic groups, finite GPU depth ties or actual render accuracy.
- `reconstruction.conditional_mask_selection`: bounded exact selection for supplied numerical block energies and unique-pixel counts, with support constraints and complete tie provenance. It is a [standalone building block](plan/SCALABLE_PHOTO_FIT.md), not yet a scalable optical fitter or an uncertainty certificate.
- `reconstruction.photo_lens_diagnostics`: replay every saved material candidate with pinned source/arrays and expose train/validation coverage by lens height and rear-composition hypothesis. This diagnoses fit limitations; it does not refit or grant acceptance.
- `../ar/src/eyewear/lens-appearance.ts`: strict descriptor consumer, CPU evaluator and shared GLSL. The isolated browser harness exercises actual exported assets.
- `../ar/src/render/lens-material.ts`, `lens-layers.ts` and `eyewear-shadow.ts`: visible/shadow adapters for authored `front_sheet_v1` optics and the explicit experimental group profile. `effective-optical-topology.ts` validates group geometry; `nearest-optical-groups.ts` owns one nearest-event map per group. Bounded composition supports four interactions, explicit overflow, opaque stops and native frame colors. The new group's strict GPU qualification remains incomplete; photo inference and mobile performance are also unfinished. See the [runtime evidence](plan/EFFECTIVE_GROUP_RUNTIME.md).

Job-level QA helpers: `python -m qa.inferred_job_summary data/jobs/<job> [...]` tabulates an inferred-grouping job's stage times, hypothesis ranking, fit support and appearance selection; `python -m qa.preview_manifest --preparation <bridge preparation report> --joint <fit stage report> --output <manifest>` builds the manifest for `ar/qa/prepared-optical-groups.mjs`, which renders the neutral candidate and every family preview through the actual AR renderer; `python -m qa.reexport_previews` re-exports a completed fit's previews with the current exporter without repeating the fit.

Registration diagnostic:

```powershell
python -m reconstruction.register --model C:/path/model.glb --photo C:/path/front.jpg --view front --output data/registration/example
```

This writes a comparison image and JSON report. Automatic contrast pixels are not a verified glasses silhouette, optical surfaces are rendered as geometric footprints regardless of transparency, and cameras are fitted to the scored image. The command therefore always leaves reconstruction quality **unmeasured**. It must not be used as an automatic model acceptance gate.

Multiview refinement of an existing model:

```powershell
python -m reconstruction.refine_photos --model C:/path/model.glb --photo front=C:/path/front.jpg --photo angled=C:/path/angled.jpg --output data/refinement/new-run
```

Use an empty output directory for standalone refinement, or the job command above for verified recovery. The stage writes pinned evidence, camera hypotheses, one shared deformation, comparison images and a report. It exports a proposal only after correspondence and triangle checks; a later footprint regression moves it to `rejected-proposal.glb`. It does not infer missing components or lens materials, and every result still has `quality_verdict=unmeasured`. [The refinement contract](plan/GEOMETRY_REFINEMENT.md) describes the checks and remaining limits.

Run all current tests from this directory with `python -B -m pytest tests -q -p no:cacheprovider`. `python -m unittest discover` does not run the pytest-style classes (for example tests/test_modeler_instruments.py, test_modeler_observe_cost.py and test_agentic_executor.py). For a fast loop add `-m "not slow"`: it deselects the tests marked `slow` (host Blender, or longer than about 15 s). Tests that read real artifacts under the ignored `data/` folder (saved BSA runs, modeler jobs and pilots, segmented runs) or need host Blender skip on a clean clone. These tests establish local mathematical and software properties, not end-to-end reconstruction fidelity.

For reproducible native and GPU rendering checks, see [the conformance commands and limitations](plan/LENS_CONFORMANCE.md).
