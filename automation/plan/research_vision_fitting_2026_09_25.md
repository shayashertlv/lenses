# GitHub research: masks, correspondence, cameras and bounded fitting

Research date: 2026-09-25. Scope: the existing `segmented_ar_v1` glasses reconstruction automation, not the live Lenses root application. Read-only research: no installs, model downloads, inference, provider submissions or application changes. Repository and license facts below were checked against upstream sources; eyewear performance is unmeasured unless explicitly described as existing local evidence.

## Decision

The most useful near-term additions are **HQ-SAM2 for boundary proposals**, **LightGlue with DISK plus PoseLib for sparse, verified frame correspondences**, and **PyTorch3D for a bounded silhouette-fitting experiment**. **VGGT-1B-Commercial** merits a separate camera-seed experiment. None establishes true lens shape, metric dimensions or optical material identity from two studio photographs.

The largest avoidable mistake would be treating familiar repo names as uniformly permissive: LightGlue's default SuperPoint extractor has different restrictions; VGGT's default sample fetches its original noncommercial checkpoint; VGGT-Omega and nvdiffrast are restricted; EfficientLoFTR changed to a project-registration license on current main. These are source observations, not a full dependency/legal audit.

## Fit to the existing implementation

Local files inspected: `README.md`, `plan/SEGMENTED_AR_JOB.md`, `reconstruction/photo_apertures.py`, `region_engine.py`, `camera.py`, `camera_pose_selection.py`, `automatic_articulation.py`, `structured_refinement.py`, `edge_correspondence.py`, and `qa/part_probe_audit.py`.

- The lens detector already runs a pinned, offline 256×256 MobileNet LR-ASPP head on full-image and contrast crops. The receipt also already contains the frame-segmentation weights. A new download is not the first step for exploring frame masks.
- The region engine currently imports **Ultralytics' SAM2 implementation**. Upstream Meta SAM2 has Apache-2.0 code/checkpoint terms; the Ultralytics implementation has its own AGPL-3.0 licensing. An official upstream adapter could reduce dependency/license complexity, but parity with the pinned existing implementation must be measured. This is not a claim that the existing private research use violates any license. [SAM2 terms](https://github.com/facebookresearch/sam2/blob/2b90b9f5ceec907a1c18123530e92e794ad901a4/README.md#license), [Ultralytics license](https://github.com/ultralytics/ultralytics/blob/main/LICENSE).
- Current camera fitting uses candidate silhouettes and bounded Powell optimization. Structured fitting binds immutable observations to source triangles/barycentric coordinates, allows separate temple articulation, and limits shared deformation. Camera updates preserve independently supported arm evidence.
- Image feature matches belong in the photographic evidence layer. They cannot replace exact provider-to-segmentation triangle correspondence, winding checks or source lineage.
- A whole-glasses rigid SfM model is wrong when temples move between photos. Use the front assembly for camera evidence, and treat left/right temples as separately articulated parts. Reflections, transparent lens interiors, uniform backdrops and silhouette extrema are not stable material-point landmarks.

## Deep checks and concrete integration experiments

### 1. HQ-SAM2 and official SAM2: compare boundary evidence, preserve alternatives

The HQ-SAM2 artifact is a real released checkpoint and code path, not just a paper. Upstream compares it with SAM2.1 under shared box prompts and reports a small COCO AP improvement; that is useful reason to test, not evidence of better transparent lenses. Its example can return a single mask; our adapter should retain alternate prompt/crop hypotheses and known domains rather than silently replacing ambiguity. [HQ-SAM2 code and model description](https://github.com/SysCV/sam-hq/blob/e696978d60352dc9a26b12631cd91781502c6546/sam-hq2/README.md).

Experiment: reuse the frozen 24-photo baseline and known-camera rendered product views. Hold prompt locations and crop policies fixed. Compare the current detector, existing SAM2, official SAM2 and HQ-SAM2 using independent annotations of lens aperture, frame and uncertain/reflected areas. Measure boundary distance, rim contamination, missed thin strips and failure by product; IoU alone hides narrow-structure failure. Keep source-photo and generated-render scores separate.

Integration boundary: implement a proposal adapter matching `describe()`/`propose()` contracts, pin source revision and checkpoint SHA, and freeze outputs before geometry optimization. Do not assign optical part roles solely from a new mask.

### 2. LightGlue + DISK + PoseLib: independent anchors where evidence exists

Actual pretrained LightGlue matcher variants are available. Its repository explicitly distinguishes the matcher from its extractors; copy-pasting the first example selects SuperPoint. DISK is the cleaner first pairing for this project. LightGlue has CPU as well as GPU benchmarks, so a small experiment need not begin with a new GPU service. [Pinned implementation notes](https://github.com/cvg/LightGlue/blob/eb42fee2d71449efb0aa5c10549752b5d75384d8/README.md).

Experiment: match only original photographic pixels; use masks to restrict accepted anchors to opaque front structure. Audit duplicate left/right lens symmetry, repeated logos, shadows, specular highlights and background matches. Keep photometric matches distinct from fixed 3D surface observations: a photo-to-photo match becomes a `SurfaceObservation` only after an independently defensible source-triangle binding.

PoseLib supplies robust pose/fundamental estimators and unknown-focal variants, but explicitly warns that focal recovery from a fundamental matrix can fail or give invalid values. A near-planar front, little parallax or independently cropped catalog images can remain degenerate even with many matches. [PoseLib estimators and focal warning](https://github.com/PoseLib/PoseLib/blob/db542cc2be5827307bd2326fca7ab390db2af2ee/README.md).

Success means more independently verified anchor coverage and lower held-out reprojection error, with no loss of arm support. Match count, model confidence and RANSAC inlier count alone are insufficient.

### 3. VGGT: camera hypotheses only, explicit checkpoint selection

The repo has actual training and inference code, camera matrices and COLMAP export with optional bundle adjustment. The commercial checkpoint is gated and requires agreeing to share contact information; no access was requested. **The pinned README still shows `VGGT.from_pretrained("facebook/VGGT-1B")` in its example**, although its update explains that only `VGGT-1B-Commercial` permits commercial usage. Record both repo and checkpoint identities. [Pinned README](https://github.com/facebookresearch/vggt/blob/a288dd0f14786c93483e45524328726ab7b1b4ce/README.md), [model gate](https://huggingface.co/facebook/VGGT-1B-Commercial).

Experiment: export a few alternative camera seeds, including both full-photo and documented masked-input variants. Convert the OpenCV camera convention explicitly to our bounded projection, preserving resize/crop transforms. Score using unchanged image evidence and the existing camera/temple support guard. Reject a seed if it needs shape distortion to compensate for wrong pose.

The inference hypothesis is that a learned prior sometimes escapes a bad silhouette basin. We have no evidence it recovers accurate glass surface depth. Lens depth can describe the background or reflections. Metric dimensions remain unobserved without supplied scale.

### 4. PyTorch3D: faster gradients do not resolve missing evidence

Official tutorials optimize camera position and fit mesh geometry from rendered silhouettes/textures; they are executable algorithm examples rather than pretrained reconstruction models. [Camera tutorial](https://pytorch3d.org/tutorials/camera_position_optimization_with_differentiable_rendering), [mesh fitting tutorial](https://pytorch3d.org/tutorials/fit_textured_mesh).

The worthwhile adaptation is a renderer backend under existing low-dimensional shared-shape and hinge variables. Preserve vertex/face order, source bindings, optical grouping and guarded displacement limits. Do not copy the tutorial's sphere-to-object free-vertex deformation into the delivery path. Use the existing renderer for final independent render comparisons; PyTorch3D's soft silhouette probability is not lens transmittance, and its standard shading does not implement the current optical contract.

First measure coordinate parity and finite-difference gradient correctness on synthetic controlled cases, then compare convergence and held-out error with current SciPy fitting. Native Windows setup is a real engineering risk: the install documentation's listed Torch versions stop at 2.4.1 while this job pins 2.7.1. That is documentation/support uncertainty, not proof of incompatibility. Use a separate WSL/Linux environment if a native build becomes costly. [Pinned install instructions](https://github.com/facebookresearch/pytorch3d/blob/978cd99221b9e0a6a568f1d427854d73363265cf/INSTALL.md).

### 5. SAM3 / 3.1: local execution and caching, not automatic semantic acceptance

The current repo contains image inference, finetuning examples and gated weights under a custom SAM License covering code and weights. The March 2026 SAM3.1 improvement centers on multiplexed multi-object video tracking; this does not demonstrate a gain on our small static-photo jobs. [Pinned 3.1 release notes](https://github.com/facebookresearch/sam3/blob/2345a4ad109ac29c569da749c91d84f10dc08c40/RELEASE_SAM3p1.md), [license](https://github.com/facebookresearch/sam3/blob/2345a4ad109ac29c569da749c91d84f10dc08c40/LICENSE).

A local adapter could replace some paid mask calls with immutable cached outputs. It must preserve all prompt/score/mask alternatives and snapshot the exact model. The existing experiments already expose omitted optical strips and reflected duplicates, so local execution alone is not a quality fix. Keep comparing lens, frame, bridge and temple concepts against source photos and known-camera renders. A renderer's clean background may make segmentation easier while still inheriting a geometrically incorrect generated model.

### 6. Why attractive alternatives are deferred

- **nvdiffrast:** the pinned license's section 3.3 restricts non-NVIDIA use to noncommercial research/evaluation without direct or indirect monetary gain. Its title includes “Commercial,” which is easy to misread. This blocks treating it as an unrestricted production default. No separate license was investigated or obtained. [Exact license](https://github.com/NVlabs/nvdiffrast/blob/253ac4fcea7de5f396371124af597e6cc957bfae/LICENSE.txt).
- **VGGT-Omega:** its September checkpoint is a real current release, but the pinned license restricts both the materials and their outputs/results to noncommercial research. It does not inherit VGGT-1B-Commercial's permission. [Exact license](https://github.com/facebookresearch/vggt-omega/blob/48b23c8ce72c9a8fcf987f0d7f43d8e4870759f6/LICENSE).
- **EfficientLoFTR:** current main requires free registration for organizational project use, including development/testing. This is not a model run authorization and we did not submit a registration. Outdoor training also gives less direct evidence for studio eyewear than its matching speed might suggest. [Exact current terms](https://github.com/zju3dv/EfficientLoFTR/blob/07e9c1401e71e9c556b1fda9d86d060af36ba176/LICENSE).
- **MASt3R/DUSt3R:** use as literature/comparison references until a suitable licensing path exists; code and checkpoint constraints are separate. They still assume useful common visual structure across views.
- **RoMaV2:** inspect the DINOv3 and checkpoint terms before use. Its loader downloads weights by default, so our offline execution policy needs an explicit local-checkpoint adaptation. Dense background correspondence can look numerically impressive while supplying no frame geometry evidence. [Loader](https://github.com/Parskatt/RoMaV2/blob/95c9968145c8906b7b59383258e9f73b02853d89/src/romav2/romav2.py).
- **Facial landmark and try-on repos:** the verified search results mostly locate a wearer's face or glasses on a face. I did not verify a maintained, pretrained repository that identifies product-photo bridge/hinge/lens landmarks across standalone catalog views. Such repositories should not be presented as a solved landmark stage for this pipeline.

## Proposed order and evaluation contract

1. Establish small independent frame/lens annotations on the existing frozen corpus; include rimless, thin wire, clear, tinted and mirrored designs. Reserve product identities as well as images where practical.
2. Compare already-retained frame weights and official SAM2/HQ-SAM2 under a frozen prompt protocol. Gate on thin-structure coverage and contamination, not just average mask overlap.
3. Run DISK+LightGlue and PoseLib as an evidence-only sidecar. Save all matches, image transforms, spatial coverage, degeneracy flags and audited inliers. Do not move geometry yet.
4. Evaluate VGGT-1B-Commercial camera seeds only after obtaining its checkpoint under the correct terms. Compare against current cameras without changing the evaluation inputs.
5. Prototype PyTorch3D fitting only if camera/edge evidence is sufficient. Preserve the canonical source and verify topology, triangle lineage and actual-AR output exactly as today.

Report every product, including no-match and no-improvement cases. Track frozen held-out reprojection/boundary error, front/temple support, camera ambiguity, runtime, memory, source displacement and the fraction of cases requiring review. Do not select masks, tune cameras and claim accuracy on the same observations. For a two-photo product without an independent view, say independent reconstruction accuracy remains unmeasured.
