# GitHub research: optics, frame appearance, delivery and visual QA

Research date: 2026-09-25. Scope: 15 repositories screened against the current glasses photo-to-AR automation, with deeper inspection of six practical candidates and several license blockers. This is a source/documentation assessment; no repository was installed, no weights or asset datasets were downloaded, no inference was run, and no application code was changed. Network reads of public documentation, licenses and repository metadata were used.

## Decision

The best immediate work is stronger validation and feature-preserving use of the simplifier already present. The best appearance experiment is Marigold IID on opaque frame regions. Mitsuba 3 is the strongest longer-term optical reference and fitting workbench, provided its models are explicitly mapped to our effective optical profile. None of the surveyed repositories establishes transparent, gradient or colored-mirror lens identity from our few uncalibrated catalog photos, or directly supplies a verified `LENSES_lens_appearance` asset.

Read locally: `README.md`, `plan/SEGMENTED_AR_JOB.md`, `plan/SEGMENTED_AR_RESULTS_2026_09_23.md`, `../ar/README.md`, `qa/part_lod_probe.py`, `qa/part_lod_probe.mjs`, `reconstruction/intrinsic_frame_appearance.py`, `reconstruction/compact_glb.py`, and function/loader searches. Current outputs are approximately 120k–126k triangles and 5–7 MB. The existing reduction already uses attribute-aware meshoptimizer with boundary and extrema locks. The runtime implements symmetric effective reflection/transmission, not general volume refraction, separate front/back coatings or internal reflections. These facts change which external projects are useful.

## Detailed practical checks

### 1. glTF-Validator: the lowest-risk addition

The official validator checks GLB structure, schema/reference consistency, binary accessor values and image issues, producing a JSON issue report. It has a Node package and Windows executable build path. Its published supported-extension list does not include `LENSES_lens_appearance`. [Official README](https://github.com/KhronosGroup/glTF-Validator/blob/main/README.md), [license](https://github.com/KhronosGroup/glTF-Validator/blob/main/LICENSE).

**Our seam:** add a read-only validator report to generated source, post-LOD/pre-optics asset, and final delivery. Bind tool version, candidate hash, errors and warnings in the job journal. Treat an unknown custom extension as an expected recorded limitation, while keeping existing strict optical reader and receipt checks mandatory. This would catch conventional file defects through an implementation independent of our exporter. A pass does not certify group identity, normals, optical response, phone performance or appearance.

**Pilot:** run the five current products plus deliberately malformed fixture copies: out-of-range indices, non-finite accessor data and missing extension declarations. Measure false positives and make ordinary glTF errors fail delivery. No GPU, models or API costs are needed.

### 2. meshoptimizer: improve policy rather than replace a working tool

Upstream supports attribute error weights, explicit vertex locking, border protection and priority flags. The simplifier can stop above its requested triangle budget when topology/error limits forbid further changes. Its `Prune` option can delete isolated components, including components containing locked vertices; `simplifySloppy` gives up topology/seam preservation. [Simplification documentation](https://github.com/zeux/meshoptimizer#simplification), [MIT license](https://github.com/zeux/meshoptimizer/blob/master/LICENSE.md).

**What is already present:** `qa/part_lod_probe.mjs` calls `simplifyWithAttributes`, preserves original attribute and image bytes, uses `LockBorder`, and locks axis extrema. Optical parts constrain normals; frame parts also constrain UVs/colors. The Python probe measures bidirectional sampled surface deviation and five silhouette views. Calling meshoptimizer a missing capability would be inaccurate.

**High-value delta:** lock source-bound lens/frame boundaries, nasal contact geometry, hinge interfaces and accepted thin optical fragments. Use per-part screen-space error and minimum feature coverage rather than only total target triangles. Do not turn on component pruning or sloppy simplification for tiny screws, rimless mounts or thin lens strips. Evaluate any newer flags against the pinned installed version before use. Triangle changes require fresh optical preparation; old face IDs and bindings cannot be reused.

**Pilot:** retain existing 120k-ish candidates as controls, test two lower budgets on all five products, and add close-up views of bridge, lens edge, hinges and logos. Pass only with unchanged semantic membership, strict export/load success, bounded local feature loss and measured phone benefit. Area-weighted surface sampling alone can miss a visually important tiny piece.

### 3. Marigold IID: strongest immediately testable frame appearance hypothesis

Two released models are relevant. IID Lighting predicts albedo, diffuse shading and an additive residual in linear space. IID Appearance predicts albedo in **sRGB**, but roughness and metallicity in linear space. Both model cards recommend an effective processing resolution around 768 pixels; their uncertainty maps require ensembles larger than two. Their weights use CreativeML Open RAIL++-M rather than the repository's Apache license. [Lighting model card](https://huggingface.co/prs-eth/marigold-iid-lighting-v1-1), [Appearance model card](https://huggingface.co/prs-eth/marigold-iid-appearance-v1-1).

The repository documents Ubuntu/Python 3.10/CUDA 11.7 on RTX 3090 and recommends WSL2 for Windows. This is evidence of a tested environment, not a claim of a minimum VRAM requirement or a benchmark on our host. [Code/setup](https://github.com/prs-eth/Marigold), [pinned code license](https://github.com/prs-eth/Marigold/blob/2bfbdeae5d10a50b71f1ba20c865d46e480f6010/LICENSE.txt).

**Our seam:** feed source photo frame regions into a separately cached proposal stage. Project only supported predictions through the existing source-bound cameras and UV surface tracks in `intrinsic_frame_appearance.py`. Preserve logos, tortoiseshell pattern and uncovered atlas areas. Compare inferred corrections to `separate_frame_tracks`, whose current conservative rule requires three views and agreeing dark observations. A learned map should propose an additional variant, not silently weaken that support rule.

**Lens exclusion is essential:** these output channels do not estimate lens absorption, angular mirror color, through-lens background or our group identity. Opaque-frame metallicity is not evidence that a lens has a mirror coating. Do not turn albedo into an optical transmission value. Keep different output color spaces explicit to avoid a double-gamma bug.

**Pilot:** RayBan tortoiseshell, clear Miu hardware and Oakley frame, retaining untouched controls. Score held-out photo agreement and actual-AR lighting changes; separately inspect logo edges and material pattern preservation. Record seed, weight revision, input hash and proposal coverage. Native Windows portability, runtime/memory use and eyewear fidelity remain unmeasured.

Pinned weight revisions observed via the model APIs: lighting `08c3930bb641abf786ba44ce92547507ebefbc16`; appearance `e7280a0a0fc5a0df0b36050882b3d8b77da22fd9`.

### 4. Mitsuba 3: optical reference, not a ready-made lens fitter

Mitsuba offers Python-defined materials and differentiable scene parameters, spectral/polarization variants, LLVM CPU execution and CUDA/OptiX GPU execution. Official documentation reports Windows support and prebuilt wheels. No pretrained model is required. [Repository](https://github.com/mitsuba-renderer/mitsuba3).

Its dielectric and thin-dielectric models provide useful reference transport, but meaningful refractive boundaries are required. The thin-dielectric model accounts for internal reflection terms that our effective AR profile intentionally does not implement. A physically richer renderer can therefore fit an image with parameters our runtime cannot reproduce. [Official BSDF reference](https://mitsuba.readthedocs.io/en/latest/src/generated/plugins_bsdfs.html).

**Our seam:** first build synthetic lens-response fixtures using known geometry, camera and environment, then compare against `ar/qa/canonical-lens-runtime.mjs`. Separately create a differentiable implementation of the exact effective response used by `LENSES_lens_appearance`, or use Mitsuba-derived response tables only as bounded descriptor proposals. Validate every emitted descriptor through `write_optical_group_candidate`, the strict reader and actual AR multi-environment rendering.

**Best useful experiment:** freeze lens geometry/normals; vary plausible source camera distance and a low-dimensional studio environment jointly with tint/coating parameters. Keep competing explanations and evaluate reserved photos. This directly targets Oakley/INVU front-versus-rear mismatch and unmeasured absorption, but unknown lighting/material ambiguity remains. General refraction or a separate back coating would require a deliberate runtime contract expansion, not merely an imported material.

The exact license is permissive BSD-3-Clause-style **plus an enhancement contribution grant**, not safely summarized as an unmodified SPDX BSD license. [Pinned license at `d22318c`](https://github.com/mitsuba-renderer/mitsuba3/blob/d22318ca55d64049acc00edafe14f0e4f5d6fe23/LICENSE). Dependencies must be reviewed for the selected CPU/GPU distribution.

### 5. glTF-Transform: useful only with our extension represented explicitly

The SDK supports custom extensions through registered `Extension`/`ExtensionProperty` classes. References represented through its property graph can follow document transforms. A correct custom read/write implementation is required for round-trip processing. This is a genuine integration mechanism, not automatic preservation of arbitrary proprietary JSON. [Custom extension documentation](https://gltf-transform.dev/extensions), [MIT license](https://github.com/donmccurdy/glTF-Transform/blob/main/LICENSE).

**Our seam:** initially use inspection and controlled processing of pre-optics frame assets. To touch canonical assets, implement every optical descriptor/group reference, preserve source semantic identity and produce a new verified receipt. Our `compact_glb.py` explicitly tracks reindexing and active semantics; generic prune/join/dedup/quantize/meshopt operations cannot be substituted behind its existing receipt.

Do not pipe `candidate.glb` through a blanket optimize command. Joining equal-looking lens materials may destroy distinct physical groups, and vertex quantization can invalidate normal/coincident-interface checks. A generic viewer screenshot is not a valid optical acceptance test.

**Pilot:** exact no-op round trip on a copied fixture, with descriptor equality, group cardinality, strict loader and same-render checks, before enabling one transform at a time. Compression decoder registration also needs explicit AR support; the inspected loader search found no MeshoptDecoder, DRACOLoader or KTX2Loader setup in the eyewear/render directories.

### 6. pixelmatch and PIQ: supplement human/model review with bounded numerical evidence

Pixelmatch compares equally sized images, supports anti-alias handling and yields diff pixels/counts. It is dependency-light and runs in Node. [README](https://github.com/mapbox/pixelmatch/blob/main/README.md), [ISC license](https://github.com/mapbox/pixelmatch/blob/main/LICENSE).

**Our seam:** use exact same-camera, same-lighting AR snapshots for changes expected to preserve appearance. Measure optical interior, frame, logo/hardware and boundary bands separately; put lossless diff images beside existing anonymous/reversed-order review cards. A one-pixel lost rimless strip should not disappear inside an excellent whole-image score. Allow calibrated antialias tolerance, but report edge-band loss independently.

PIQ supplies PyTorch image quality metrics, including nonlearned SSIM families. Start only with those; learned metrics can introduce separate weights and licensing/download behavior. [README](https://github.com/photosynthesis-team/piq/blob/master/README.rst), [Apache license](https://github.com/photosynthesis-team/piq/blob/master/LICENSE).

Pixel/SSIM scores are not acceptance evidence between a studio photo and an arbitrary AR environment: camera mismatch and unknown illumination dominate. Keep photo fidelity and same-render regression as separate experiments. Neither metric resolves clear-versus-mirror ambiguity over white backgrounds.

## Lower-priority delivery and research findings

**Basis Universal / KTX-Software:** useful for reducing frame texture transfer and GPU texture storage. Start with isolated opaque frame atlases and compare both fine logos and tortoiseshell pattern under the current renderer. Texture compression does not lower triangle count or remove the canonical optical passes/capacity checks. KTX2 adoption requires loader/transcoder assets and measured phone decode/memory behavior. [Basis repository](https://github.com/BinomialLLC/basis_universal), [KTX tools](https://github.com/KhronosGroup/KTX-Software). KTX's license inventory explicitly identifies a non-open-source ETC fallback decoder which can be excluded with `LIBKTX_FEATURE_ETC_UNPACK=NO`; do not label the entire bundled distribution simply Apache-2.0. [Pinned KTX license](https://github.com/KhronosGroup/KTX-Software/blob/dd3b8b0a788c9e61ca835bec3c11961d5ffe2d6f/LICENSE.md).

**IntrinsicAnything:** released single-image intrinsic predictions are potentially useful on frames, but the current README still marks multiview inverse rendering as forthcoming. The current `LICENSE` is **Project Registration License v1.0 (2026)**: organizational project use, including internal development/testing, requires registration. Do not reuse older summaries that call current code Apache-2.0. [README](https://github.com/zju3dv/IntrinsicAnything/blob/master/README.md), [pinned license](https://github.com/zju3dv/IntrinsicAnything/blob/5fa5ec07f7e09101710c80bc95738fabb0cbfc80/LICENSE). The linked Hugging Face Space exists at revision `9d4566436935a6c99287c05e71e177b4a4753422`, but its current API card metadata returned no license; individual checkpoint rights were not cleared. Prefer Marigold for the first pilot.

**NVIDIA differentiable stack:** nvdiffrec has unusually relevant joint optimization and documented Windows setup, but its high-end GPU expectation and older CUDA/PyTorch setup need a separate environment. nvdiffrecmc studies material/light decomposition with Monte Carlo rendering. These are useful literature/code references; neither is a licensed commercial drop-in. [nvdiffrec setup](https://github.com/NVlabs/nvdiffrec/blob/abf3a34b1eb6e782abffefc2462c7e9bcd89f9bb/README.md), [nvdiffrecmc setup](https://github.com/NVlabs/nvdiffrecmc/blob/c61d41b475b651640dcf6b13f4a0ffea9a399f03/README.md). Exact code-use restrictions are in [nvdiffrast license](https://github.com/NVlabs/nvdiffrast/blob/253ac4fcea7de5f396371124af597e6cc957bfae/LICENSE.txt), [nvdiffrec license](https://github.com/NVlabs/nvdiffrec/blob/abf3a34b1eb6e782abffefc2462c7e9bcd89f9bb/LICENSE.txt), and [nvdiffrecmc license](https://github.com/NVlabs/nvdiffrecmc/blob/c61d41b475b651640dcf6b13f4a0ffea9a399f03/LICENSE.txt). The misleading phrase “1-Way Commercial” in nvdiffrast's title does not grant general commercial use: its use limitation reserves commercial use to NVIDIA/affiliates.

**TSGS:** unlike a pure novel-view renderer, it extracts first-surface depth for **mesh reconstruction**. Its March 2026 updates add prior options and camera-matrix fixes. It needs multiview data, COLMAP and normal/de-lighting priors; its showcased TransLab data are glassware rather than catalog eyewear. Thus output format alone is not the reason to defer it. Capture mismatch, no optical material/semantic contract, external priors and license restrictions are the reasons. [README](https://github.com/longxiang-ai/TSGS/blob/73d3f984de0e9b47012b535f303248b0164da17c/README.md). Commercial use is prohibited and modifications must be open source under its stated terms. [Pinned TSGS license](https://github.com/longxiang-ai/TSGS/blob/73d3f984de0e9b47012b535f303248b0164da17c/LICENSE.md).

**TRAN-D:** an actual released ICCV 2025 implementation, including Grounded SAM2 preprocessing, custom 2DGS rasterizer and physics-based scene updating. It targets transparent depth in scenes, with tested CUDA 11.8/Python 3.10–3.11 and Docker instructions. Potentially useful ideas: separate object/background and object-aware geometric support. It neither estimates colored coatings nor emits a verified AR lens asset. [Code](https://github.com/jeongyun0609/TRAN-D), [primary paper](https://openaccess.thecvf.com/content/ICCV2025/papers/Kim_2D_Gaussian_Splatting-based_Sparse-view_Transparent_Object_Depth_Reconstruction_via_Physics_ICCV_2025_paper.pdf). The segmentation license is [Apache-2.0](https://github.com/jeongyun0609/TRAN-D/blob/c7457e7dcfb10ae8bb574c02045b2921837bb77b/tran-d_seg/LICENSE); the reconstruction module inherits a [non-commercial research/evaluation license](https://github.com/jeongyun0609/TRAN-D/blob/c7457e7dcfb10ae8bb574c02045b2921837bb77b/tran-d_gs/LICENSE.md). Do not treat its segmentation license as applying to the whole pipeline.

## Suggested experimental order

1. Add independent glTF standards validation and region-specific exact-render regressions. This protects future research and costs no provider calls.
2. Improve the existing reduction's semantic/feature policy; quantify savings at equal local visual error and on a real phone.
3. Run the bounded Marigold opaque-frame pilot with untouched controls, source-bound projections and held-out photos.
4. Build a tiny Mitsuba optical-reference corpus and an explicit mapping to the current descriptor; only then attempt inverse fitting.
5. Evaluate frame-only KTX2 delivery if profiling shows texture storage/transfer is a meaningful bottleneck.

Success means a measurable improvement over the saved candidates under the actual AR renderer and preserved evidence/recovery contracts. It does not mean a pretrained model returned a plausible image, a general glTF viewer loaded the file, or a published paper reports a high score on another object/capture regime.
