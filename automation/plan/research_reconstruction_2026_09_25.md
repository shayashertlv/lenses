# GitHub research: reconstruction and editable parts

Research date: 25 September 2026. Scope: existing product photographs and optional dimensions to accurate, editable glasses GLBs for this automation. This is a source review, not a new model benchmark. No repositories, checkpoints or datasets were installed; no inference or paid calls ran.

The local context reviewed was `README.md`, `SEGMENTED_AR_RESULTS_2026_09_23.md`, `API_COMPARISON_RESULTS_2026_09_23.md`, and the current segmentation/role integration in `reconstruction/segmented_job.py` and `reconstruction/part_role_inference.py`. The existing Tripo source geometry, textures, bounded face correspondence, optical assignment and actual-AR checks remain the comparison baseline. Our own two-product experiment already makes another broad generator replacement a lower priority than improving separation and geometry evidence.

## Recommendation

**GeoSAM2 is the best new repository to investigate first in this group.** It offers a plausible local route from a seed lens mask to source-mesh face labels. It can complement the current provider segmentation without changing generation. Its authors explicitly say thin geometry and transparent surfaces remain difficult, so this is a targeted experiment, not an expected immediate replacement.

**SAMPart3D is a slower second segmentation baseline. PartCrafter and HoloPart are later experiments for structured generation and missing-part completion.** Neither should bypass source preservation or establish product truth. PartField is scientifically relevant but its non-commercial code license rules it out as an ordinary dependency for the commercial automation. Several superficially attractive alternatives have material licensing or release gaps.

All fit judgments below are inferences from the methods, released code and our local failure cases. Public demos are not evidence that a method preserves a particular glasses SKU, lens boundary, hinge, logo or optical coating.

## 1. GeoSAM2 — first experiment

The released workflow consumes twelve mesh renders containing color, depth, normals and camera metadata, plus a seed mask or point prompts. It propagates the mask and exports per-face labels. The release includes inference code but intentionally excludes training/fine-tuning code. Its documented runtime is Linux, Python 3.10+ (tested 3.12), PyTorch 2.3+, Blender 4.0+, and preferably CUDA; CPU is supported but slow. No tested VRAM floor is stated. [Repository instructions](https://github.com/VAST-AI-Research/GeoSAM2/blob/b5de23c60ab487d407b623d394a1614f9714761c/README.md)

Code and checkpoints are Apache-2.0. The roughly 154M-parameter model has fp32 and bf16 checkpoint variants. The model card explicitly identifies thin/wire-like geometry, highly transparent surfaces and per-mesh postprocessing tuning as limitations. It produces part instances rather than semantic class names. [Checkpoint and limitations](https://huggingface.co/VAST-AI/GeoSAM2), [code license](https://github.com/VAST-AI-Research/GeoSAM2/blob/b5de23c60ab487d407b623d394a1614f9714761c/LICENSE)

**Integration inference:** preserve `generation['model']`, render it using GeoSAM2's camera convention, and seed masks using the existing lens detector on those exact renders. Import only its face-label proposals, map them back to immutable source triangles, and construct alternative part GLBs that retain original material/UV data. Continue through `qa.part_probe_audit.bounded_correspondence`, `part_role_inference.infer_part_roles`, reduction and optical preparation. Catalog-photo masks cannot be passed as though aligned to a synthetic render.

The source makes the adapter requirement concrete: `load_mesh_with_faces` rebuilds geometry with separate vertices for triangle corners; the visualization exporter assigns vertex colors; `complete_labels` removes small components and fills unlabeled faces from nearby labels. These defaults can erase precisely the small lens strip or hinge evidence we care about. Preserve the raw labels/unknowns, compare postprocessing as an explicit alternative, and never adopt its diagnostic GLB as our textured source. [Reviewed implementation](https://github.com/VAST-AI-Research/GeoSAM2/blob/b5de23c60ab487d407b623d394a1614f9714761c/utils/inference_utils.py)

The last/default-branch commit observed is **2026-05-07**, and the repository has a single commit. That is a released research implementation with little visible maintenance history, not a mature SDK. [Pinned revision](https://github.com/VAST-AI-Research/GeoSAM2/commit/b5de23c60ab487d407b623d394a1614f9714761c)

## 2. SAMPart3D — independent segmentation baseline

SAMPart3D renders sixteen RGB/depth views in Blender and trains a per-object MLP over its released PTv3-object backbone. Multiple segmentation scales can then be evaluated using the trained object checkpoint. That is materially more work than a single pretrained inference call. Its installation guide reports a **24 GB RTX 4090**, Python 3.10, CUDA 12.1 and PyTorch 2.1.0, with pointops, FlashAttention, tiny-cuda-nn and GPU HDBSCAN dependencies. Treat it as a Linux CUDA research worker; native Windows readiness is unverified. [Workflow](https://github.com/Pointcept/SAMPart3D/blob/6a508d145be5cecd7e80bce6e4248ea7abbd71b7/README.md), [installation](https://github.com/Pointcept/SAMPart3D/blob/6a508d145be5cecd7e80bce6e4248ea7abbd71b7/INSTALL.md)

The repository uses MIT and the linked backbone model card declares MIT. The backbone card has older project naming, so pin the exact model file and its terms before integration rather than treating the name as a sufficient provenance record. [Code license](https://github.com/Pointcept/SAMPart3D/blob/6a508d145be5cecd7e80bce6e4248ea7abbd71b7/LICENSE), [backbone card](https://huggingface.co/yhyang-myron/SAMPart3D)

**Integration inference:** export alternative source-bound partitions, not automatically named lenses. Compare its scales against current Tripo segmentation on the same retained meshes, especially VB's strip and Miu hardware. This gives a different kind of part evidence, but it still depends on rendered appearance and cannot certify transparent-lens boundaries. It cannot correct a nonexistent or distorted source surface. Preserve point-to-face mapping and verify the full source-face inventory before optical assignment.

Last observed default-branch commit: **2025-05-04**, a README update. [Pinned revision](https://github.com/Pointcept/SAMPart3D/commit/6a508d145be5cecd7e80bce6e4248ea7abbd71b7)

## 3. PartCrafter — structurally relevant, lower priority than retained-source segmentation

PartCrafter generates multiple part meshes jointly from one image. The released launcher accepts a requested part count, with a hard range of **1–16**. Code and object-level pretrained weights are MIT. The authors tested Debian 12 with NVIDIA H20 GPUs; a community Windows route is linked, but no authoritative minimum VRAM is supplied. [Repository](https://github.com/wgsxm/PartCrafter/blob/3d773bf02fad51c7ab31a5615573fec93b287b30/README.md), [launcher](https://github.com/wgsxm/PartCrafter/blob/3d773bf02fad51c7ab31a5615573fec93b287b30/scripts/inference_partcrafter.py), [weights](https://huggingface.co/wgsxm/PartCrafter)

The default launcher downloads and loads `briaai/RMBG-1.4` even when its removal flag is absent. BRIA's model is non-commercial by default, with a separate commercial agreement route. An MIT badge therefore does not make the full default runtime unrestricted. Use a small adapter around the core pipeline and an approved input mask, avoiding that download/load altogether. [Actual launcher dependency](https://github.com/wgsxm/PartCrafter/blob/3d773bf02fad51c7ab31a5615573fec93b287b30/scripts/inference_partcrafter.py), [BRIA terms](https://huggingface.co/briaai/RMBG-1.4)

**Integration inference:** test a separate initializer through `existing_glb`, with two lenses, front structure and two temples as hypotheses rather than fixed guaranteed identities. Source photography must stay unchanged: the optional generative style-transfer mode can change the product and contaminate fidelity evaluation. This model is a geometry proposal generator; independent photo and AR checks, texture transfer, material assignment and mobile reduction would remain. Its new triangles cannot satisfy the existing retained-Tripo segmentation bijection by definition.

The promising contribution is decomposed representation, not proof of accurate rimless geometry. Last observed commit is **2026-04-16**, a merge adding VLM part suggestions and style transfer. [Pinned revision](https://github.com/wgsxm/PartCrafter/commit/3d773bf02fad51c7ab31a5615573fec93b287b30)

## 4. HoloPart — completion after segmentation

HoloPart consumes a mesh already split into surface parts and uses diffusion to complete them into entire components. Its instructions explicitly begin with an existing mesh plus a face-mask array and recommend external segmentation methods. It releases MIT code and MIT-declared weights, using a Python 3.10/PyTorch CUDA setup. The reviewed README gives no reliable minimum VRAM. [Repository](https://github.com/VAST-AI-Research/HoloPart/blob/48dd632c9a7412e6688573bb4f153e0ade7e7325/README.md), [model card](https://huggingface.co/VAST-AI/HoloPart), [license](https://github.com/VAST-AI-Research/HoloPart/blob/48dd632c9a7412e6688573bb4f153e0ade7e7325/LICENSE)

**Integration inference:** use only when photographs support a missing rear temple surface or an incomplete lens patch. Keep the observed part frozen where possible, run completion as a separate proposal, and measure overlap/displacement/occlusion against the retained source. The current strict correspondence contract must remain mandatory for ordinary segmentation; completion needs a different lineage describing genuinely new geometry. It must not be called successful source-preserving segmentation. Hallucinated thickness, filled lens holes and changed rim profiles are particularly important failure cases for glasses.

This is attractive because it operates after our strongest existing generation instead of requiring us to abandon it. It still cannot determine the actual shape behind an occluder from the generated mesh alone. Last observed default-branch commit is **2025-04-11**; only three commits are visible. [Pinned revision](https://github.com/VAST-AI-Research/HoloPart/commit/48dd632c9a7412e6688573bb4f153e0ade7e7325)

## 5. PartField — strong methodological fit, commercial blocker

PartField accepts meshes or point clouds and learns continuous part features that support hierarchical clustering, correspondence and interactive selection. Its clustering hierarchy terminates at source triangle faces. The released environment uses Python 3.10, PyTorch 2.4 and CUDA 12.4; no general VRAM guarantee is stated. The README warns that fragmented connectivity can degrade clustering and offers preprocessing or alternative adjacency; those operations must not silently modify our source topology. Only its Objaverse-trained model is released, because the authors could not release the PartNet-trained variant under that dataset's licensing constraints. [Repository](https://github.com/nv-tlabs/PartField/blob/373025dbd283bb44cc4a6dc78c99994dbc91de32/README.md), [actual checkpoint](https://huggingface.co/mikaelaangel/partfield-ckpt/blob/main/model_objaverse.ckpt)

The decisive limit is code license section 3.3: non-commercial research and educational use only, except for NVIDIA. The linked checkpoint page does not establish a separate permissive commercial grant. Do not call it an MIT alternative or put it into the commercial automation by default. [Pinned license](https://github.com/nv-tlabs/PartField/blob/373025dbd283bb44cc4a6dc78c99994dbc91de32/LICENSE)

**Integration inference if separately licensed:** retain the face-feature hierarchy as an alternative-part proposal source, using current multi-view role evidence to choose candidate optical unions. Texture-derived lens/frame similarity and adjacent near-coincident surfaces remain potential confusions; part clustering is not optical classification. Last observed default-branch commit: **2026-06-02**, README update. [Pinned revision](https://github.com/nv-tlabs/PartField/commit/373025dbd283bb44cc4a6dc78c99994dbc91de32)

## Important defer/reject details

- **Hunyuan3D-Part:** P3-SAM has automatic and point-prompted segmentation with published safetensors; the documented tested stack is Python 3.10, PyTorch 2.4/CUDA 12.1 plus Sonata dependencies. X-Part's open release is explicitly the light version. Its official demo says it cleans the mesh and provides aligned face IDs; a face ID belongs to the cleaned mesh until independently mapped to our source. The [community license](https://github.com/Tencent-Hunyuan/Hunyuan3D-Part/blob/e96be065375438962375b55326416291342958a7/LICENSE) excludes the EU, UK and South Korea, including use/display of outputs, and contains an additional permission condition above one million MAU at the version's release date. These are concrete distribution constraints, even if the current worker is in Israel. [P3-SAM instructions](https://github.com/Tencent-Hunyuan/Hunyuan3D-Part/blob/e96be065375438962375b55326416291342958a7/P3-SAM/README.md), [official demo implementation](https://huggingface.co/spaces/tencent/Hunyuan3D-Part/blob/main/app.py). Last observed commit: **2025-12-05**.

- **SAMesh:** appealing zero-shot mask lifting through normal/matte/other renders, with a documented Python 3.12/CUDA 11.8 setup. But the reviewed upstream root and package metadata contain no license, and `/LICENSE` returns 404. A downstream plugin's MIT license cannot grant rights to unlicensed upstream code. This is a reuse gate, not proof the authors intended restrictive terms. The last observed commit is **2026-07-17**; a **2026-05-21** merge includes face-ID, texture and platform fixes. [Root tree](https://github.com/gtangg12/samesh), [package metadata](https://github.com/gtangg12/samesh/blob/26fb0ca01682fe97638e102b2f0876b2fc7d95d6/pyproject.toml), [commit history feed](https://github.com/gtangg12/samesh/commits/main.atom).

- **UltraShape:** takes an input image and coarse mesh and regenerates finer geometry. The project's data processing explicitly fills holes and thickens thin structures: this is a poor default assumption for thin rims, drill-mount hardware and narrow lens borders. Its [GitHub license](https://github.com/PKU-YuanGroup/UltraShape-1.0/blob/5e8dcef05df101ab00ab6cd5fdd0ed0c74fbca66/LICENSE) is Tencent Hunyuan3D-2.1 community, while the [checkpoint card](https://huggingface.co/infinith/UltraShape) declares Apache-2.0 and identifies Hunyuan3D-2.1 as its base. Treat the discrepancy as unresolved. CUDA/PyTorch 2.5.1 is documented, with low-memory switches but no guaranteed floor. Last observed commit: **2026-01-06**. [Refinement instructions](https://github.com/PKU-YuanGroup/UltraShape-1.0/blob/5e8dcef05df101ab00ab6cd5fdd0ed0c74fbca66/README.md)

- **TRELLIS.2:** released MIT code/model and separate shape-conditioned texturing are useful for a controlled frame-only texture ablation. Official support requires Linux and an NVIDIA GPU with at least **24 GB**, tested on A100/H100. Its advertised opacity attribute is not evidence of physical lens transmission or our front/rear optical contract. Our existing saved single-seed results on two products were weaker than Tripo and all raw lenses remained opaque. Local self-hosting does not invalidate that evidence. Dependencies have their own terms. Last observed default-branch commit: **2026-06-05**; a later repository `pushed_at` is not a later default-branch implementation change. [Code/model license and requirements](https://github.com/microsoft/TRELLIS.2/blob/75fbf0183001ed9876c8dbb35de6b68552ee08bd/README.md)

- **Hunyuan3D-2.1:** shape and texture stages are separable; the documented VRAM needs are **10 GB shape / 21 GB texture / 29 GB both**. README claims Windows/macOS/Linux support, but its published setup compiles CUDA-related extensions, so actual host compatibility still needs a small worker test. Code and weights have Tencent's custom community terms, including territorial restrictions; this is not a standard permissive license. Last observed commit **2025-10-17** updated the license. [Runtime and models](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/82920d643c0dc2f7bfd7255f45f62d386edfe60c/README.md), [license](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/82920d643c0dc2f7bfd7255f45f62d386edfe60c/LICENSE)

- **TripoSG:** an MIT single-image shape generator, documented for CUDA with at least **8 GB VRAM**. This is a different model from the hosted H3.1/v3.5 route that produced our best retained textured assets. It does not inherit that measured quality. The default pipeline auto-downloads BRIA RMBG-1.4, so an approved mask adapter is again required. Its SDF geometry would need fresh optical segmentation and texturing. Last observed commit **2025-04-18**. [README](https://github.com/VAST-AI-Research/TripoSG/blob/fc5c40990181e2a756c4e0b1c2f4d6b5202faf8c/README.md), [weights](https://huggingface.co/VAST-AI/TripoSG)

- **SAM 3D Objects:** model and code available, with gated checkpoint access and custom SAM License. Official setup needs **Linux 64-bit and at least 32 GB NVIDIA VRAM**. Its single-image masked-object reconstruction is designed around natural scenes and occlusion. That may help future wearer-photo input, but does not directly improve the current fused lens/frame boundary problem. Its quickstart exports splats; use an explicit mesh path and our optical compiler if testing, since splats are not editable optical GLBs. Last observed commit **2026-06-02**; README records encoder-weight release on June 1. [Setup](https://github.com/facebookresearch/sam-3d-objects/blob/f91db411c50efee93d8db7aeb323885650f6f722/doc/setup.md), [license](https://github.com/facebookresearch/sam-3d-objects/blob/f91db411c50efee93d8db7aeb323885650f6f722/LICENSE), [overview](https://github.com/facebookresearch/sam-3d-objects/blob/f91db411c50efee93d8db7aeb323885650f6f722/README.md)

- **PartPacker:** editable parts from a single image is relevant, but the [code license](https://github.com/NVlabs/PartPacker/blob/178d6c9408ecde857e6e716bab2763df6ce8bdc0/license.md) and [model card](https://huggingface.co/nvidia/PartPacker) limit ordinary use to non-commercial research. Do not spend commercial integration effort unless separately licensed. Last observed commit **2025-06-26**.

- **Stable Fast 3D:** useful inexpensive preview generation with UVs and de-lighting; default inference is approximately **6 GB VRAM**, with experimental Windows/MPS and CPU support. The applicable [Stability Community License](https://github.com/Stability-AI/stable-fast-3d/blob/ff21fc491b4dc5314bf6734c7c0dabd86b5f5bb2/LICENSE.md) includes commercial registration and a revenue threshold requiring a separate license above $1 million annual revenue, alongside distribution/attribution terms. Preview speed does not establish thin-rim or exact-product quality. Last observed default-branch commit **2025-01-22**. [Runtime](https://github.com/Stability-AI/stable-fast-3d/blob/ff21fc491b4dc5314bf6734c7c0dabd86b5f5bb2/README.md)

- **Eyewear-specific releases:** the [ECCV 2020 repository](https://github.com/wang-yating/EyeglassesReconstruction) is an empty implementation promise at the inspected revision: README and teaser, no released model or training/inference pipeline. A closer [2024 thin-eyeglasses paper](https://arxiv.org/abs/2408.05402) describes template keypoints, camera estimation and progressive free-form deformation with differentiable rendering. No corresponding working public implementation was verified in this search. The methodological lesson is useful: silhouette/keypoint-constrained deformation of a valid glasses template may be more faithful than unconstrained image-to-3D generation. It is a research design direction, not a repo we can plug in.

## Proposed experiment, bounded to current failure cases

1. Freeze the existing five retained Tripo sources, segmentation results, photo manifests and AR outputs. Add held-out products/views before claiming a catalog-wide improvement. Do not regenerate source geometry for the first segmentation comparison.
2. Run a **GeoSAM2 face-label proposal adapter** first, using exact camera-aligned seed masks. Preserve raw and postprocessed alternatives, unknown faces, source hash and face mapping. Evaluate Miu's thin lens/hardware boundary and VB's ambiguous strip before scaling to all five.
3. Require unchanged positions, winding, textures and UVs for the source-preserving candidate, backed by the existing bounded correspondence audit. A segmentation algorithm's output part count or appealing colored mesh is not a sufficient success criterion.
4. Measure lens-face precision and recall against independently reviewed boundary labels, using surface area as well as triangle counts; include thin-strip and hardware subsets. Measure cross-view contamination, missing boundaries, runtime, peak VRAM and amount of per-product tuning. Keep the current ambiguity reports and full unknown-face inventory.
5. Only then compare SAMPart3D as a genuinely different segmentation baseline. Generate PartCrafter/HoloPart hypotheses in a separate track with new geometry lineage, independent photo checks and the same optical/mobile/actual-AR gates. Do not make generated alternative shapes the ground truth for evaluating retained sources.

Success would be fewer incorrect optical boundaries or less per-product intervention at equal or better source/texture preservation. Merely reducing API cost, returning separately named objects, rendering successfully or passing the triangle budget would not demonstrate a product-fidelity improvement.
